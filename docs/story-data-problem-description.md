# 当前剧情目录与解析问题详细描述

## 1. 文档目的

本文档说明 GamesMcp 当前原神剧情数据的实际问题，重点回答：

1. 页面表现出了哪些错误；
2. 错误对应源数据和解析流程中的哪一层；
3. Wiki 为什么可以按系列、章节和任务展示；
4. AnimeGameData 中是缺少正文，还是缺少正文与任务之间的关系；
5. 在正文只使用单一源数据的前提下，哪些问题可以恢复，哪些问题不能安全推断。

Wiki 只作为任务归类、章节关系和顺序的外部核对依据。最终展示的对白正文仍应只来自项目当前使用的 AnimeGameData，不能把 Wiki 台词复制进数据库。

审计对象：原神当前 r8 数据。  
源快照：data/upstream/AnimeGameData-current。  
审计时间：2026-09-21。  
详细证据：[原神世界任务解析与 Wiki 对照审计](F:/Project/GamesMcp/docs/genshin-world-quest-wiki-audit.md)。

---

## 2. 总体结论

当前问题不是单一的“解析器漏了几条对白”，而是四类问题叠加：

```text
源数据关系不完整
        ↓
任务、章节、系列和对白无法正确关联
        ↓
导入后的目录出现未分类、重复、乱序
        ↓
页面又把内部子任务和质量占位数据直接展示给用户
```

最重要的判断是：

> Wiki 中出现的内容，不应简单判断为“源数据没有”。目前已经确认至少有一些任务的对白字面存在于 AnimeGameData 的 TextMap 中，但任务到对白节点之间的关系没有被当前快照完整保留，或者没有被解析器识别。

需要区分三种情况：

| 情况                                       | 含义                       | 能否修复                       |
| ------------------------------------------ | -------------------------- | ------------------------------ |
| 文本和对白关系都存在，但解析器没有读到     | 解析器问题                 | 可以直接修复                   |
| TextMap 有文本，但任务、角色或顺序关系缺失 | 源数据关系缺失             | 可通过可审计的关系映射部分恢复 |
| 任务元数据存在，但源快照没有文本和关系     | 源快照不完整或属于内部任务 | 不能凭空恢复，只能标记或隐藏   |

过去页面把这三种情况混在一起，统一显示成空任务、部分任务或未分类章节，导致问题看起来比实际更混乱。

## 3. 页面层面的具体问题

### 3.1 目录标题顺序错误

用户看到的现象：

- 同一大型支线的序曲、第一章、第二章和终章顺序不稳定；
- 章节 ID 或主任务 ID 较小的任务被错误排在前面；
- 同一系列被地区节点或配置章节打断；
- Wiki 中属于同一系列的任务，在项目中分别出现在多个未分类章节或散篇任务下；
- 父任务、章节任务和具体可玩的子任务混在同一个排序层级。

预期结构应当是：

```text
地区
└── 大型任务系列
    └── 序曲 / 第一章 / 第二章 / 终章
        └── 具体任务
```

根因是把数据标识当成了剧情顺序：

- chapterId 更接近配置章节或功能分组，不等于剧情章节顺序；
- mainQuestId 是稳定标识符，不是剧情排序号；
- beginQuestId 只能说明配置起点；
- series 有时为空，有时只表示连续任务；
- 前后置关系需要先构建任务关系图才能排序。

直接按 ID 排序，必然会把数据顺序误当成故事顺序。

### 3.2 大型支线被拆成多个任务

典型表现：

- 水仙十字相关任务没有统一归入一个系列；
- 谐律上的咏叙诗的序曲、第一章、第二章、第三章、终章需要人工重新理解；
- 愿为一炊之梦的父任务显示为空，实际剧情分散在多个子任务中；
- Wiki 的一个系列页在项目中被拆成多个独立世界任务节点。

Wiki 不是把每条 MainQuest 自动当成一个页面。编辑者会维护系列任务、章节、前置任务、后续任务、任务流程和任务剧情。参考[世界任务编辑教程](https://wiki.biligame.com/ys/%E4%B8%96%E7%95%8C%E4%BB%BB%E5%8A%A1%E7%BC%96%E8%BE%91%E6%95%99%E7%A8%8B)和[世界任务目录](https://wiki.biligame.com/ys/%E4%B8%96%E7%95%8C%E4%BB%BB%E5%8A%A1)。

当前项目有任务实体，却缺少独立的剧情关系层：

```text
原始 MainQuest / SubQuest
        ↓
任务前后置关系
        ↓
系列 / 章节 / 页面归属
        ↓
最终目录树
```

现在许多地方实际上是“一个 MainQuest 直接生成一个目录节点”，所以未分类章节不一定代表游戏没有章节，而是项目没有可靠地完成任务到章节的映射。

### 3.3 未分类章节数量过多

当前 r8 世界任务目录统计：

| 项目               | 数量 |
| ------------------ | ---: |
| 地区节点           |   10 |
| 世界任务行         | 1426 |
| 标准化后的不同标题 | 1308 |
| 系列节点           | 1316 |
| fallback 散篇任务  | 1238 |
| derived 系列       |   67 |
| curated 系列       |    3 |

目前只有水仙十字系列、谐律上的咏叙诗、山中好长日等少量系列使用了人工确认关系。绝大多数任务都落入 fallback 的散篇任务，说明当前目录不是完整的 Wiki 风格分类。

造成 fallback 的原因包括：

1. 源字段没有给出面向玩家的系列名称；
2. series 字段只给出连续任务等粗粒度关系；
3. 章节关系分散在主任务、子任务和前后置关系中；
4. 父任务和子任务没有聚合；
5. 测试、隐藏和奖励控制任务也被纳入公开目录；
6. 没有版本化人工关系映射补充源数据缺口。

### 3.4 剧情对白阶段标签没有意义

页面把子任务或对白分组直接提升成主要导航，生成剧情对白 1、剧情对白 2、剧情对白 11 等标签。但子任务是数据结构，不一定是玩家需要看到的故事章节；有些子任务只是触发条件、移动、战斗或流程控制。

影响：

- 页面头部被大量无意义标签占据；
- 用户误以为每个标签都是独立剧情章节；
- 选择标签后只能看到部分对白；
- 父任务和子任务关系被错误表现成章节关系。

正确行为应是默认展示完整任务正文。subquestId 可以保留在内部数据或诊断页面中，但不应继续作为正文顶部的主要导航。

### 3.5 正文为空或只有部分对白

当前公开世界任务记录：

| 状态          | 数量 | 含义                     |
| ------------- | ---: | ------------------------ |
| complete      | 1302 | 有可用正文或对白关系     |
| partial       |   76 | 存在正文或结构缺口       |
| metadata_only |   48 | 只有任务元数据或任务目标 |

非完整任务原因：

- 74 条 missingDialogue；
- 2 条 missingSubquests；
- 48 条同时缺少对白和子任务关系。

在 124 条非完整记录中，122 条没有实际 BinOutput/Talk/Quest 文件，2 条仍有 Talk 文件但任务关系不完整，分别解析出 38 和 83 个对白节点。

missingDialogue 不能直接等于“源数据没有文本”。有些任务的文本字面存在于 TextMap，只是没有被关系表连接到任务。

## 4. 典型任务证据

### 4.1 无形壁障：文本存在，任务对白图缺失

参考 Wiki：[无形壁障](https://wiki.biligame.com/ys/%E6%97%A0%E5%BD%A2%E5%A3%81%E9%9A%9C)。

项目记录：

| 字段            | 当前值            |
| --------------- | ----------------- |
| 主任务 ID       | 73189             |
| 章节            | 旧语新知          |
| 系列            | fallback 散篇任务 |
| 对白节点        | 0                 |
| Talk/Quest 文件 | 0                 |
| 质量            | partial           |
| 原因            | missingDialogue   |

审计已经在同一份 AnimeGameData 的 TextMap 中找到与 Wiki 页面相符的文本：

- [TextMap_MediumCHS.json:116406](F:/Project/GamesMcp/data/upstream/AnimeGameData-current/TextMap/TextMap_MediumCHS.json:116406)
- [TextMapCHS.json:152319](F:/Project/GamesMcp/data/upstream/AnimeGameData-current/TextMap/TextMapCHS.json:152319)

但这些文本哈希没有被 DialogExcelConfigData、TalkExcelConfigData 或 BinOutput/Talk/Quest 明确关联到 73189。

事实关系是：

```text
任务元数据：有
任务目标：有
文本字面：有
文本到任务的关系：缺失
对白节点顺序：缺失
```

这是孤立文本问题，不是普通的字符串缺失问题。只接受明确 Talk/Dialog 关系会返回空正文；仅凭标题或模糊数字匹配则可能串入其他任务对白。

| --------------- | --------------- |
| 主任务 ID       | 72236           |
| 对白节点        | 0               |

| 质量            | partial         |

该案例需要进一步区分：Wiki 对白是否全部存在于 TextMap、是否分散在旧版 Talk/QuestTalk/Codex、是否只剩文本而没有角色和顺序关系，以及是否需要任务 ID 到 TextMap 哈希的版本化映射。

## 5. Wiki 与项目的根本差异

### 5.1 Wiki 展示的是编辑后的语义层

Wiki 的世界任务页面按地区、系列和章节组织内容，并由编辑者维护前置、后续、任务流程和剧情段落。它不要求页面结构与游戏内部 MainQuest 表完全一致。

参考[世界任务](https://wiki.biligame.com/ys/%E4%B8%96%E7%95%8C%E4%BB%BB%E5%8A%A1)、[世界任务编辑教程](https://wiki.biligame.com/ys/%E4%B8%96%E7%95%8C%E4%BB%BB%E5%8A%A1%E7%BC%96%E8%BE%91%E6%95%99%E7%A8%8B)和[数据组指南](https://wiki.biligame.com/ys/%E6%95%B0%E6%8D%AE%E7%BB%84%E6%8C%87%E5%8D%97)。

不能假定：

```text
一个 Wiki 页面 = 一个 MainQuest
一个 Wiki 剧情段落 = 一个 Talk 文件
一个 Wiki 章节 = 一个 chapterId
```

更接近：

```text
多个原始任务、子任务和对白文件
                ↓
       编辑者判断系列与章节关系
                ↓
        Wiki 的任务页面和剧情结构
```

### 5.2 Wiki 页面可能包含非对白信息

Wiki 任务流程可能包括前往某地、调查物件、开启机关、战斗、领取奖励、对话、剧情选项和说明文字。只有其中一部分是对白。

项目如果只解析对白文件，不可能自动得到完整 Wiki 任务流程文字；但可以从同源任务目标、对白事件和流程字段重建一部分，并明确区分对白正文与流程说明。

### 5.3 Wiki 会过滤内部记录

AnimeGameData 中可能存在 test、hidden、unreleased、发奖父任务和流程控制任务。Wiki 通常不会把这些记录作为用户可见的正式剧情页面。

项目如果把所有 MainQuest 直接展示，就会出现重复、空白和标题异常。这是源数据解析问题和公开目录筛选问题同时存在的结果。

## 6. 解析器和模型层面的根因

### 6.1 任务实体和剧情实体被过度绑定

实际剧情可能分散在 MainQuest、Chapter、Quest、Talk、Dialog、BinOutput/Talk/Quest、BinOutput/CodexQuest、TextMap 等文件中。这些文件共同构成关系图，不是一张可以直接平铺的任务表。

### 6.2 数字前缀不能作为关系证据

仅凭数字前缀、ID 长度或标题相似来连接任务和对白，可能把不同任务的对白串在一起。安全匹配应优先使用明确的主任务 ID、Talk 的 questId、QuestTalk/Talk/Quest 的 questId 或 mainQuestId、明确的文件路径和有证据的父子关系。

没有任务上下文的文本相似度只能作为候选，不能自动导入为正式对白。

### 6.3 元数据占位数组可能被误当成正文

页面正文状态、条数和加载状态必须读取真正的对白关系表。若读取主任务元数据中的占位数组，就会出现页面显示有内容但正文为空、TextMap 有文本却显示 0 条，以及 complete、partial、metadata_only 判断不可靠。

### 6.4 父任务、章节和子任务没有分层

父任务可以是系列入口，章节任务可以是目录节点，子任务才可能携带对白。三者都直接变成同一种任务页面，就会出现空父页面、重复页面和阶段标签污染。

### 6.5 角色名失败不应丢弃正文

如果角色映射失败，仍应保留对白正文，并标记角色名缺失。不能因为无法解析说话者就删除整条对白。

## 7. 筛选、搜索和状态问题

### 7.1 类型筛选没有稳定作用于最终目录树

切换到世界任务后，目录应只显示最终筛选结果。当前问题可能来自旧目录缓存、默认目录覆盖新结果或详情导航绕过筛选，表现为左侧选中世界任务但仍混入其他类型、搜索结果与目录不一致、切换语言后条件被重置。

筛选必须作用于同一份标准化目录模型。

### 7.2 关键词搜索覆盖范围不足

搜索应至少覆盖原始任务标题、显示标题、系列、章节、角色名、对白正文和任务 ID。只搜索当前页面标题，会找不到属于大型系列但标题不同的任务。

### 7.3 空状态没有区分原因

暂无正文可能表示真实无对白、文本关系缺失、任务绑定失败、筛选无结果或请求失败。这些情况必须分别显示，不能统一显示暂无正文。

## 8. 影响范围

对用户阅读的影响：

- 无法按大型支线连续阅读；
- 无法判断任务是否属于同一系列；
- 空任务和测试任务降低目录可信度；
- 部分对白缺失造成剧情断裂；
- 阶段标签让页面看起来像解析失败或重复；
- 同名任务使用户无法判断当前页面对应哪个任务。

对数据质量的影响：

- complete、partial、metadata_only 含义不够精确；
- 缺对白和缺关系被混为一类；
- fallback 系列数量过高；
- 父任务和子任务重复计数；
- 目录排序不能作为剧情顺序。

对修复流程的影响：

如果不先解决关系模型，逐个任务重新解析会反复修同类问题，且无法判断改善来自正文还是目录，最终仍会留下大量散篇和未分类节点。

## 9. 可以解决和不能凭空解决的部分

可以解决：

- 使用前后置关系和任务图恢复系列顺序；
- 使用章节、地区和明确源字段构造目录；
- 聚合父任务和子任务；
- 过滤测试、隐藏、未发布和纯流程控制任务；
- 保留同名不同 ID 并消歧；
- 修复类型筛选、关键词筛选和阶段标签；
- 修复有对白文件但绑定失败的任务；
- 对 TextMap 中存在且能唯一绑定的孤立文本进行关系修复；
- 让每条正文追溯到源文件和 TextMap 哈希。

不能安全凭空解决：

- 当前快照完全没有文本、角色和顺序信息的任务；
- 多个任务共享同一句文本且没有上下文；
- Wiki 有说明但源数据没有对应字段的非对白流程文字；
- 无法确认是正式任务还是内部占位任务的记录；
- 没有证据支持的标题相似度合并。

这些内容必须标记为源数据不可确认或需要人工关系确认，不能为了让页面看起来完整而强行拼接。

| P10  | 类型筛选失效         | 过滤后目录仍混入旧结果              | 前端缓存和最终目录模型不一致   | 高     |
| P11  | 空状态含义不清       | 所有空内容显示同一提示              | 没有质量原因分类               | 中     |
| P12  | 角色名缺失导致丢对白 | 有文本但整条被舍弃                  | 角色映射失败时未保留正文       | 中     |

## 11. 最终问题定义

当前项目已经获取了一部分原始任务和文本事实，但尚未建立足够完整、可审计的“任务—系列—章节—子任务—对白—文本”关系图；页面又把中间层数据直接暴露给用户，最终造成目录归类错误、顺序错误、空正文、部分正文、重复任务和筛选失效。

这也是为什么单纯重新解析一次不能彻底解决问题：重新解析只能重复读取当前关系，不能自动创造源数据中缺失的系列关系、父子关系和剧情顺序。

最终系统应达到：

1. Wiki 确认的系列和章节关系在目录中有明确结构节点；
2. 每个正式任务都能追溯到一个或多个原始任务 ID；
3. 每条正文都能追溯到 AnimeGameData 的源文件和 TextMap 哈希；
4. Wiki 只参与系列、章节和顺序校验，不向正文注入台词；
5. 文本存在但关系缺失的任务被单独标记并可审计；
6. 真正无对白的任务显示为仅元数据，而不是伪装成解析失败；
7. 测试、隐藏和内部控制任务不进入默认公开目录；
8. 同名任务不会错误合并；
9. 正文默认展示完整任务内容，不把内部子任务显示为大量阶段标签；
10. 类型筛选、关键词搜索、目录排序和正文分页使用同一份最终目录与正文模型。
